Blue Alliance Robotics History – API Contract

Version: 1.0

Resource: Robotics Teams

Base URL: http://localhost:3000/api

Content Type: application/json

Purpose

This document defines the REST API for the Blue Alliance Robotics History application.

The API manages FIRST Robotics Competition team information. The React frontend communicates with the Express backend through asynchronous HTTP requests.

The primary resource is teams.

Team Data Structure

Each robotics team will use the following JSON structure:

{
"id": "1",
"name": "Example Robotics Team",
"number": "1234",
"rookieYear": "2005",
"description": "Information about the robotics team.",
"history": "Historical competition information and achievements.",
"images": [
"images/team-example.jpg"
]
}

The team data contains the following fields:

id: A unique identifier generated automatically by the backend.

name: The name of the robotics team.

number: The FIRST Robotics Competition team number.

rookieYear: The year the team first competed.

description: General information about the team.

history: Historical information and competition achievements.

images: An array containing image paths associated with the team. This field defaults to an empty array.

The id is generated by the backend and is separate from the FIRST team number.

The name, number, rookieYear, description, and history fields are required. The images field must be an array and defaults to an empty array if it is not provided.

API Endpoints

3.1 Retrieve All Teams

HTTP Method: GET

Route: /api/teams

Purpose: Retrieves all robotics teams stored by the backend.

Request: No request body is required.

Success Response: 200 OK

{
"data": [
{
"id": "1",
"name": "Example Robotics Team",
"number": "1234",
"rookieYear": "2005",
"description": "Information about the robotics team.",
"history": "Historical competition information.",
"images": []
}
]
}

Error Response: 500 Internal Server Error

{
"error": {
"code": "INTERNAL_SERVER_ERROR",
"message": "An unexpected server error occurred."
}
}

3.2 Retrieve One Team

HTTP Method: GET

Route: /api/teams/

Purpose: Retrieves a specific robotics team using its unique identifier.

Example Request: GET /api/teams/1

Request: No request body is required.

Success Response: 200 OK

{
"data": {
"id": "1",
"name": "Example Robotics Team",
"number": "1234",
"rookieYear": "2005",
"description": "Information about the robotics team.",
"history": "Historical competition information.",
"images": []
}
}

Error Response: 404 Not Found

{
"error": {
"code": "TEAM_NOT_FOUND",
"message": "The requested robotics team was not found."
}
}

3.3 Create a Team

HTTP Method: POST

Route: /api/teams

Purpose: Creates a new robotics team.

Request Content Type: application/json

Request Body:

{
"name": "New Robotics Team",
"number": "5678",
"rookieYear": "2010",
"description": "A new FIRST Robotics team.",
"history": "The team's competition history.",
"images": []
}

The id is generated automatically by the backend and must not be supplied by the client.

Success Response: 201 Created

{
"data": {
"id": "4",
"name": "New Robotics Team",
"number": "5678",
"rookieYear": "2010",
"description": "A new FIRST Robotics team.",
"history": "The team's competition history.",
"images": []
}
}

Error Response: 400 Bad Request

Returned when required fields are missing, have invalid data types, or the JSON request body is malformed.

{
"error": {
"code": "VALIDATION_ERROR",
"message": "Invalid team information.",
"details": [
"Team name is required."
]
}
}

Malformed JSON requests will also return a 400 Bad Request response using the standard error response format.

Error Response: 409 Conflict

Returned when another team already uses the same FIRST team number.

{
"error": {
"code": "DUPLICATE_TEAM_NUMBER",
"message": "A team with this FIRST team number already exists."
}
}

3.4 Update a Team

HTTP Method: PUT

Route: /api/teams/

Purpose: Updates an existing robotics team's information.

PUT replaces the team's editable information. All required fields must be supplied.

Example Request: PUT /api/teams/1

Request Content Type: application/json

Request Body:

{
"name": "Updated Robotics Team",
"number": "1234",
"rookieYear": "2005",
"description": "Updated team information.",
"history": "Updated historical information.",
"images": [
"images/updated-team.jpg"
]
}

The existing id is preserved and must not be included in the request body.

Success Response: 200 OK

{
"data": {
"id": "1",
"name": "Updated Robotics Team",
"number": "1234",
"rookieYear": "2005",
"description": "Updated team information.",
"history": "Updated historical information.",
"images": [
"images/updated-team.jpg"
]
}
}

Error Response: 404 Not Found

{
"error": {
"code": "TEAM_NOT_FOUND",
"message": "The requested robotics team was not found."
}
}

Error Response: 400 Bad Request

Returned when required fields are missing, have invalid data types, or the request body is malformed.

{
"error": {
"code": "VALIDATION_ERROR",
"message": "Invalid team information.",
"details": [
"Required team fields must be provided."
]
}
}

Malformed JSON requests will also return a 400 Bad Request response using the standard error response format.

Error Response: 409 Conflict

Returned when the updated FIRST team number already belongs to another team.

{
"error": {
"code": "DUPLICATE_TEAM_NUMBER",
"message": "A team with this FIRST team number already exists."
}
}

3.5 Delete a Team

HTTP Method: DELETE

Route: /api/teams/

Purpose: Deletes a robotics team using its unique identifier.

Example Request: DELETE /api/teams/1

Request: No request body is required.

Success Response: 204 No Content

No response body is returned when the team is successfully deleted.

Error Response: 404 Not Found

{
"error": {
"code": "TEAM_NOT_FOUND",
"message": "The requested robotics team was not found."
}
}

HTTP Status Codes

The API will use standard HTTP status codes to communicate the results of requests.

200 OK indicates that a request was successful. It is used for retrieving and updating teams.

201 Created indicates that a new robotics team was successfully created.

204 No Content indicates that a robotics team was successfully deleted.

400 Bad Request indicates that the request contains invalid information, missing required fields, invalid data types, or malformed JSON.

404 Not Found indicates that the requested robotics team does not exist.

409 Conflict indicates that a team with the same FIRST Robotics team number already exists.

500 Internal Server Error indicates that an unexpected error occurred on the server.

Error Response Format

All API errors will use a consistent JSON response structure.

{
"error": {
"code": "ERROR_CODE",
"message": "A description of what went wrong."
}
}

Validation errors may also include a details array explaining which fields need correction.

The React frontend will use HTTP status codes and error messages to display appropriate feedback to users.

Data Storage

For this milestone, robotics team information will be stored in a local JSON file on the server.

The backend will read team information from this file and update it when teams are created, edited, or deleted.

A permanent database and user authentication are outside the scope of this milestone.

The backend is responsible for generating unique identifiers, validating team information, and managing all team operations.

Frontend Integration

The React frontend will communicate with the Express backend through asynchronous fetch requests.

The Vite development server will proxy requests beginning with /api to the Express backend.

The frontend will support displaying all robotics teams, viewing individual team information, creating new teams, editing existing teams, and deleting teams.

The frontend will also display loading indicators while requests are processing and appropriate error messages when requests fail.

Implementation Notes

The backend will use Express and express.json() to process JSON request bodies.

API routes will be separated from business logic to maintain an organized backend structure.

The API will be tested using Vitest. At least one automated test will verify a successful backend route handler.

The backend implementation and frontend requests must follow the routes, HTTP methods, request structures, response structures, and status codes defined in this contract.
