Debugging Analysis: React and Express Request-Response Cycle

Application: Blue Alliance Robotics History. Feature: Retrieving Robotics Teams. Endpoint: GET /api/teams.

Request-Response Analysis: For this test, we used the robotics team directory to see how the React front end communicates with the Express back end. When the teams page loads, React sends an asynchronous GET request to /api/teams using the Fetch API. The request goes through the Vite development server, which sends requests beginning with /api to the Express server running on port 3000. The GET method is used because the application is asking for existing team information instead of creating or changing a record. In the browser's Network panel, we can inspect the request URL, method, and headers. The request does not need a JSON body because it is only retrieving information, so a Content-Type header is not required. The Express server receives the request and gets the team records from its in-memory data array. When the request is successful, the server returns HTTP status 200 OK and a JSON response containing a data array with the team records. React waits for the response, checks whether the request was successful, and reads the response using response.json(). The returned information is then saved in the component's state. React updates the page to show the team information and removes the loading message. If the request fails, the application displays an error message instead of leaving the page empty. This process shows how the front end and back end work together to send, receive, and display information without reloading the entire page.
