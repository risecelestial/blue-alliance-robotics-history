Blue Alliance Robotics History – Project Handoff Summary

Project: Blue Alliance Robotics History. Application Name: Community Archives. Repository: https://github.com/risecelestial/blue-alliance-robotics-history. Original Developers: Rohanji Novas and Eric Edwards.

Application Overview: Blue Alliance Robotics History is a website about FIRST Robotics Competition teams and their history. Its goal is to organize information about teams, competitions, important events, and achievements. The original website has a historical timeline and an Original and Sustaining Teams section. Visitors can move between teams and view images using an image carousel.

Current Project Status: The project started as a website built with HTML, CSS, and JavaScript. It has since been expanded with a React front end and an Express back end. The React application uses components and page navigation to organize the interface. The Express back end provides a REST API that manages robotics team information. The API supports all four main operations: creating, reading, updating, and deleting teams. The front end sends requests to the API using fetch. The application also includes loading and error messages so users can see when information is being loaded or when something goes wrong. Vitest and Supertest are used to test the backend routes.

Important Files: The index.html file contains the original website structure. The style.css file controls its design. The script.js file manages the original timeline, team information, and interactive features. The frontend folder contains the React application and Vite setup. The backend folder contains the Express server, API routes, controllers, team data, and automated tests. README.md explains how to install and run the project. API_CONTRACT.md explains the API. KNOWN_ISSUES.md lists limitations and unfinished work. DEBUGGING_ANALYSIS.md explains a request and response between React and Express. Teamlog.md contains development notes.

How to Run the Project: To run the React application, open a terminal in the frontend folder, run npm install, and then run npm run dev. To run the back end, open another terminal in the backend folder, run npm install, and then run npm start. Both servers need to stay running while testing the full-stack application. The React application uses the Vite proxy to send API requests to the Express server at port 3000. To run the backend tests, open a terminal in the backend folder and run npm test.

Current Limitations: The backend currently stores team information in an in-memory array instead of a permanent database. Any changes made through the API disappear when the server restarts. Some team information and historical events are still sample content and need to be replaced with researched and verified information. The project does not currently include user accounts or authentication. The original website and the newer React application are separate versions of the project.

Future Development: The next developer should first run both applications and understand how the front end and back end communicate. They should keep the original website working while improving the React application. A database could be added to save team information permanently. More real FIRST Robotics teams, photographs, competition results, and historical events should be researched and added. Search and filtering could also be improved. Any new changes should be tested and documented so future developers can understand the project.

Handoff Notes: The React and Express applications are already implemented, so the next developer does not need to start those parts from the beginning. The best place to continue is improving the data, adding more features, and making the application more complete. All changes should be tested before being merged into the main branch.
